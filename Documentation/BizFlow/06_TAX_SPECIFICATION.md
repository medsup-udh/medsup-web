## 5. Tax Engine — ข้อกำหนดการคำนวณ

### 5.1 ลักษณะ

- **Pure function** ไม่มี I/O: รับข้อมูลเอกสาร คืนผลคำนวณ — ใช้ร่วมกันทั้งเบราว์เซอร์ (แสดงผลสด) และเซิร์ฟเวอร์ (ค่าที่บันทึกจริง) จากโค้ดชุดเดียว (FR-TAX-10)
- ใช้ Decimal arithmetic เท่านั้น (BR-GEN-03); มีหมายเลขเวอร์ชัน (`tax-1.0.0`) บันทึกในเอกสาร
- เปลี่ยนกฎการคำนวณ = เวอร์ชันใหม่; เอกสารเก่าคงค่าเดิม (ไม่คำนวณใหม่)

### 5.2 Input / Output

| Input | ชนิด | หมายเหตุ |
|---|---|---|
| `price_mode` | EXCLUSIVE / INCLUSIVE | |
| `vat_rate` | decimal(5,2) | จาก tax_settings ตามวันที่เอกสาร |
| `lines[]` | quantity (≤ 3 ตำแหน่ง), unit_price (≤ 4 ตำแหน่ง), line_discount {type, value}, tax_category | |
| `doc_discount` | {type: NONE/PERCENT/AMOUNT, value} | |

| Output | คำอธิบาย |
|---|---|
| ต่อบรรทัด | gross_amount, line_discount_amount, net_amount, doc_discount_alloc |
| ต่อประเภทภาษี | subtotal, ส่วนลดท้ายเอกสารที่เฉลี่ยมา, ยอดหลังส่วนลด |
| ระดับเอกสาร | subtotal, line_discount_total, doc_discount_amount, vatable_base, zero_rated_amount, exempt_amount, out_of_scope_amount, vat_amount, grand_total, amount_in_words |
| คำเตือน | เช่น ส่วนลดเกินยอด, ราคา 0, ยอดติดลบ |

### 5.3 กฎการคำนวณ (ลำดับ 7 ขั้นตาม PART 4.2)

| รหัส | ขั้น | กฎ | ระดับ |
|---|---|---|---|
| TR-01 | 1. จำนวน × ราคาต่อหน่วย | `gross = round2(qty × unit_price)` ต่อบรรทัด | [V0] รูปแบบมาตรฐาน |
| TR-02 | 2. ส่วนลดรายบรรทัด | % → `round2(gross × p / 100)`; จำนวนเงิน → ค่าที่กรอก; ต้อง ≤ gross; `net = gross − discount` | [V0] |
| TR-03 | 3. รวมมูลค่า | `subtotal = Σ net` และแยกผลรวมตามประเภทภาษี | [V0] |

**เหตุผลที่คิด VAT ระดับเอกสาร:** ใบกำกับภาษีแสดงภาษีจำนวนเดียว การปัดเศษรายบรรทัดแล้วรวมกันอาจต่างจากการคำนวณจากฐานรวม 1–2 สตางค์ ทำให้ยอดในใบกำกับภาษีไม่ตรงกับ `ฐาน × 7%` (ป.86/2542 ข้อ 10 ระบุผลเมื่อภาษีในใบกำกับไม่ตรงกับที่คำนวณได้ [V1]) — ให้ผู้เชี่ยวชาญยืนยันใน OI-T13

### 5.4 การแสดงผลบนใบกำกับภาษีเมื่อคิดราคารวม VAT

ราคาต่อหน่วยและยอดรายบรรทัดแสดงตามที่ตกลง (รวม VAT) แต่สรุปท้ายเอกสาร **ต้อง** มีบรรทัด "มูลค่าสินค้าที่ไม่รวมภาษีมูลค่าเพิ่ม" และ "ภาษีมูลค่าเพิ่ม 7%" แยกกัน (TC-11) — รูปแบบนี้ต้องยืนยัน (OI-T06)

1. รอบเลขคำนวณจาก `doc_date` ตามเขตเวลา Asia/Bangkok — ไม่ใช่เวลาที่กดบันทึก และไม่ใช่ UTC (FR-NUM-08) เช่น กดออกเวลา 00:30 น. วันที่ 1 ม.ค. ตามเวลาไทย (= 17:30 UTC ของ 31 ธ.ค.) ต้องได้ลำดับของปีใหม่ถ้าวันที่เอกสารเป็น 1 ม.ค.

3. การเปลี่ยนจาก A ↔ B ↔ C มีผลได้เฉพาะต้นรอบถัดไป (BR-NUM-07) เพื่อไม่ให้มีสองรูปแบบในรอบเดียว
4. ใช้ลำดับแยกต่อสาขาที่ออกเอกสาร (FR-NUM-01) — ถ้ามีหลายสาขาออกใบกำกับภาษี แนะนำเพิ่ม `{BR}` ในรูปแบบเพื่อไม่ให้เลขเหมือนกันข้ามสาขา
